# 录屏版本后的两项补充优化

## 录屏包一致性验证

新增 `evaluation.verify_demo_package`：核对页面和运行JSON的哈希、源报告的哈希、逐案结果与来源的一致性、首次通过和程序修正次数，以及完整案例覆盖。删除失败Route、把真实调用重标成离线或换入另一份运行结果都能检测。它只验证文件与记录一致性，不是签名、语义正确证明或独立准确率评估。

```bash
.venv/bin/python -m evaluation.verify_demo_package --directory outputs/latest-flow-2026-10-16/recording
.venv/bin/python -m evaluation.verify_demo_package --directory outputs/latest-flow-2026-10-16/recording-offline
```

两包均通过，0次模型调用。真实调用记录仍是2/3最终检查、0/3首次通过、2条有程序修正、1条保留失败；离线复验是5/5最终检查、1/5首次通过、4条有程序修正。没有把两者混成同一成功率。

页面和案例JSON与固定录屏分支逐字节相同；仅补充manifest里的校验字段。GitHub CI增加这两包的检查。

## 可选 JSON 输入压缩

Vertex CLI新增 `--compact-context`，默认关闭。它只移除JSON字符串**以外**的格式空白，不选取或删减材料，不改写key顺序、数字字面量、Unicode、字符串中的空白、引号和转义；非JSON提示原样保留。政策、原始材料和反证全部在。该选项进入续跑指纹，不会与原输入方式混用checkpoint；成功调用的元数据记录原始与发送字节数及编码方式。

下面命令是需要真实模型的用法示例，本次**没有执行**：

```bash
.venv/bin/python -m ryde_resolve.run_demo --case DISP-003 --judge vertex --advocate teammate-vertex --thinking-level LOW --compact-context --max-calls 5 --transient-retries 0 --judge-repairs 0 --output-dir outputs/compact-live-local
```

现有三条真实运行的Judge上下文离线测量：

| 案例 | 原始字节 | 压缩字节 | 减少 |
| --- | ---: | ---: | ---: |
| Route | 99,054 | 95,605 | 3.48% |
| No-show | 93,910 | 90,738 | 3.38% |
| Fare | 71,925 | 69,510 | 3.36% |

这些是输入字节数，不是tokens或费用。没有新做模型对照，因此不宣称降低了费用、耗时，或保持了模型行为。该幅度有限，保留全部材料比删除可能重要的反证更适合当前录屏阶段。更激进的语义摘要尚无材料保真与模型效果证据，不默认启用。
