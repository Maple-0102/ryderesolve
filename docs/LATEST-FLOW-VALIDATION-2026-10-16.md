# 2026-10-16 最终流程验证与修复

本轮目标：在现有 Evidence + Advocate v0.3 接口上验证完整流程，保留真实失败，并准备可复现的录屏版本。未修改两个队友的 vendor 代码或公共接口。

## 已完成的修复

- Judge 提示与逐条论点指南强调：引用用户投诉只能证明有人这样说，不能自动证明当次行程发生过。Advocate 自报的 `claim_type` / `evidence_status` 不视为证明。
- 权限不足且必须转人工时，原有保守修正继续保留：降低没有事件记录支持的论点评价，保留原始输出与修改审计。
- 新增严格限定的 Fare 检查：只有既有主记录已独立满足政策条件、决定和金额均正确、没有强制人工条件时，才允许降低不受证据支持的非关键论点，并修正与逐条评价冲突的双方汇总。**不补证、不改金额、不改决定、不提升任何论点的可信度。** 若裁决依据依赖相关陈述、存在相反证据、未知编号、未知政策条件或其他检查失败，则拒绝此修正。
- 原始 `check_judge` 校验未放宽。任何修正后的候选仍必须完整通过同一检查。
- 缓存指纹纳入实际使用的 vendor 提示、schema 等文件；修改这些文件不会误用旧 checkpoint。
- 页面增加“检查原因与下一步”，关联出问题的原句、说明和处理建议，区分技术失败与政策要求转人工。
- 增加限次真实评估、零调用离线复验、独立案例录屏包生成工具；保留失败候选，不覆盖旧报告。
