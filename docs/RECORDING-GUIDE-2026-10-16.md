## 打开方式

克隆仓库后，直接用浏览器打开：

`outputs/latest-flow-2026-10-16/recording/index.html`

这是本轮三个官方案例**真实模型调用的保存记录**。打开、切换、点击来源都不会调用模型，无需配置 Gemini 或腾讯云账号。不要把它称为现场实时运行。另有 `recording-offline/index.html`，是旧输出经当前程序复验的5题对照，页面明确标为离线复验，不能混作本轮真实新调用。

完整流程仍是：Evidence → 乘客／司机各自开场 → 双方回应 → Judge → 程序检查 → 建议或人工交接。第二轮双方收到相同争点，能看到对手开场，不能偷看对手回应。政策、材料不足时不能靠反复讨论补齐事实。

## 可以照着讲的版本

**开场**：我们的项目叫 RydeResolve，解决乘客和司机对收费各执一词时，客服需要反复核对材料的问题。我们让 Evidence 整理证据和政策，两个 Advocate 分别代表乘客与司机提出和回应论点，Judge 再结合原始材料给出建议。程序最后还会检查权限、引用和金额，不能让模型的一段解释直接变成退款。

**Fare**：这次展示的是实际调用模型后保存的记录，打开页面不会再次花费额度。这里原报价是12新元，实际收了16.50新元，原始记录显示没有通知乘客。沿着证据编号可以打开对应原文。双方的开场和回应都保留下来，Judge需要逐条说明采纳、反驳或证据不足，最后在政策允许的情况下建议退还4.50新元。

请注意，这次原始模型输出没有首次通过。页面会展示程序降低了哪些没有独立事件记录支持的论点评价。修正没有创造新证据，也没有改动金额和决定；只有独立主记录、条件和其他完整检查都通过，才允许保留这个建议。这仍不代表每段自然语言都已经被证明正确。

**Route**：这个案例体现权限边界。额外距离超过AI可以自主处理的范围，必须由人工决定。新调用里，模型却把一个人工权限问题标成了已解决，还混淆了几条陈述与事实的证据范围。校验器拒绝了这个输出，页面保留失败原因，金额为空。这是我们希望系统做到的保护：即使模型给出有说服力的解释，也不能自行消除规则限制。

**No-show**：这里不是技术失败，而是正常的政策交接。预约时间、取消时间都有记录，但免费等待与另一条no-show门槛的关系没有明确。我们把缺口列给人工或政策负责人，没有凭猜测给出最终收费结论。人工以后怎么处理，应单独记录处理人、理由和依据。

**补证与交接**：我们还有本地工作台，可以预览新材料与旧快照的差异，注明来源后再确认重跑。补材料只允许一轮，重建双方论点，并保留旧结果。人工登记不会覆盖AI建议，也不执行真实退款。若录屏展示虚构的人工作业或补充材料，要明确说是演示数据，不能当成官方政策澄清。

**收尾**：这个原型的重点是把证据、双方观点、政策限制和处理记录连起来，让客服能复核每一步。三个官方案例这轮有两条通过最终检查，一条被安全拦截，原始模型首次通过为零；这不是准确率测试。代码有380项本地程序测试通过。后续最需要的是主办方政策澄清、更多独立案例和人工评估，不能用少量已知样例宣称已经达到生产效果。

## 可选：打开工作台展示人工交接

按 README 安装 Python 依赖。录屏时不用 `--live`：

```bash
.venv/bin/python -m ryde_resolve.workbench --directory outputs/recording-workbench --port 8765 --import-run outputs/latest-flow-2026-10-16/recording/r21-noshow-original.run.json
```

打开 `http://127.0.0.1:8765`，展示已导入的 No-show 和交接入口即可。不需要点击“开始案件”，那个入口在默认模式下用的是离线占位 Agent。录制结束按 Ctrl+C 停止服务。

Windows将 `.venv/bin/python` 替换为 `.venv\Scripts\python.exe`，其他路径可保持不变。默认工作台不开启付费模型。不要录到密钥、ADC、账单或私人账号页面。

## 用语与素材核对

- Gemini 是本次实际运行模型；WorkBuddy / CodeBuddy 等只讲团队确实完成并有截图支持的开发使用，不能说成未经验证的运行时接入。
- 展示官方样例不等于真实运营数据。合成通知对照必须明说是团队构造。
- 可以讲“建议部分退款4.50”，不能讲“已退款”。可以讲“程序检查通过”，不能讲“所有推理都正确”。
- 不把历史离线5/5说成这次真实新调用5/5。最新真实记录是2/3最终检查、0/3原始首次通过。
- 上面是建议剪辑节奏；最终视频时长保持5–8分钟，按组委会最终提交要求检查格式和链接可访问性。
